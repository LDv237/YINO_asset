# 容量探针（组件级）

本目录是 `tools/capacity_probe.py` 对主结果 9821 的 WAL 做的 2x/5x 补充实验。它只测**处理流水线**这一层：同一个 `Pipeline`、同一份 `config.json`，前面加 200,000 容量的有界队列；按原始平均接收速率 722.783 条/s 的 2x/5x 重新节拍，跑完整 650,542 条 WAL 记录。

## 结果

| 倍率 | 目标/实际 offered | 处理条数 | 队列峰值 / 上限 | 队列满等待 | 处理 p50 / p99 / p999 | signals / fills | 与 live 一致 |
|---:|---:|---:|---:|---:|---:|---:|---|
| 2x | 1,445.6 条/s | 650,542 | 117 / 200,000 | 0 | 0.052 / 0.321 / 0.743 ms | 47,127 / 6,437 | 是 |
| 5x | 3,613.9 条/s | 650,542 | 539 / 200,000 | 0 | 0.042 / 0.300 / 0.769 ms | 47,127 / 6,437 | 是 |

## 文件

- `summary.json`：2x/5x 合并结果；
- `summary_2x.json`、`summary_5x.json`：单次运行结果；
- 口径、边界和下一步实验见 `docs/11_容量与过载实验.md`。

## 边界

边界同 `docs/11_容量与过载实验.md` §1/§4：只测处理流水线，不含 WebSocket、WAL 写线程、派生 I/O、磁盘变慢和真实交易所过载，不是端到端容量证明。

## 复现

```bash
python scripts/extract_main_run.py 运行材料/01_主结果_现货_9821
python tools/capacity_probe.py --run 运行材料/01_主结果_现货_9821 \
  --rates 2,5 --out 运行材料/04_容量探针
```

2x 约 450 秒，5x 约 180 秒。
