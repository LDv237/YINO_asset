# 交付材料索引

这个目录是我按用途整理给面试官的材料，完整运行目录（WAL、派生数据、日志、回放）还在 `artifacts/runs/`，这里没有重复打包。建议按下面的顺序看。

## 1. 建议阅读顺序

1. `00_交付说明.md`：项目、材料清单、复现入口、实测摘要。
2. `01_代码与文档/一诺笔试交付包.zip`：代码、测试、全部中文文档、配置和离线样本。
3. `02_正式运行/`：正式 15 分钟运行的摘要、清单、原始 WAL、JSONL、CSV。
4. `03_执行变体/`：现货只做多 interval、同一 WAL 对照、严格落盘版本，以及各版本的成交明细。
5. `04_验证证据/`：成交编号、现金最低值、交易活跃度、异常终止恢复、健康状态。
6. `05_运行日志/`：三次运行的控制台日志。
7. `06_完整运行目录.txt`：完整 run 目录的位置。

## 2. 文件说明

每个目录里具体放了什么，我列在下面：

| 目录 | 文件 | 说明 |
|---|---|---|
| 00 | `00_交付说明.md` | 交付材料总说明 |
| 01 | `一诺笔试交付包.zip` | 代码、文档、测试、样本 |
| 02 | `config.json` | 正式运行的完整配置快照；replay 使用 |
| 02 | `正式运行摘要.json` | 抽象做市 / interval 的 summary |
| 02 | `正式运行清单.json` | 文件清单与 WAL 分段 SHA-256 |
| 02 | `原始WAL.tar.gz` | 388,394 条原始记录的 WAL 压缩包 |
| 02 | `原始行情.jsonl.gz` | 人类可读 JSONL，388,394 行 |
| 02 | `行情CSV.zip` | aggTrade/bookTicker/depth/快照 CSV |
| 03 | `只做多_interval_摘要.json` | 只做多 / interval |
| 03 | `只做多_同一WAL对照_摘要.json` | 同一 WAL 的受控对照 |
| 03 | `只做多_严格落盘_摘要.json` | `fsync_policy=always` 的 15 分钟运行 |
| 03 | `成交明细/*.csv` | 各变体的成交记录 |
| 04 | `成交编号完整性.json` | aggTrade ID 重复/缺口审计 |
| 04 | `现金最低值审计.json` | 期末余额与逐笔过程最低值 |
| 04 | `交易活跃度_interval.json` | 07:00 UTC 桶排名 3/47 |
| 04 | `交易活跃度_严格版.json` | 08:00 UTC 桶排名 4/47 |
| 04 | `异常终止恢复.json` | 强制终止后的 WAL 前缀检查 |
| 04 | `健康状态修复.json` | 关停前/后 health 证据 |
| 05 | `*.log` | 正式运行、只做多、严格版控制台日志 |

完整数据仍在 `artifacts/runs/`，这里放的是按用途挑出来的副本。

本次交付的 15 分钟 run 的执行结果（signals/fills/PnL/digests）由同一份原始 WAL 用 quote-time guard + tick 取整重算；`05` 下的控制台日志是原始 live 采集，日志末尾的 fills 计数是重算前的 live 执行值，不能和 02/03 的重算摘要直接对照。延迟、资源、健康仍是原始 live 数据。02 的正式运行摘要和 03 的两份 live-run 摘要里，`execution_replay` 字段明确记录了重算来源、quote-time guard、tick 取整和重算时间；同一 WAL 对照本身是一份 replay 摘要，不需要这个字段。
