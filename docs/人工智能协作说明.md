# 人工智能协作说明

本文简要说明本项目在开发过程中如何使用 AI 编程助手，以及哪些判断和验证由我负责。

## 1. 使用方式

- 在明确需求、接口和验收标准后，我让 AI 助手生成模块初稿、测试用例和文档草稿；
- 对生成的代码逐段审查，不把“能生成”当作“能运行”；
- 在本地运行 `pytest`、短时真实行情、WAL 校验和回放摘要，确认行为符合接口；
- 对网络 API、并发顺序、数值符号等关键点，用最小脚本、独立参考实现或手算结果复核。

## 2. 由我负责的决策

- 数据源选择与网络可达性判断；
- 系统架构、WAL 持久化策略、队列与反压设计；
- 断线恢复、快照重建、只做多/严格落盘等语义；
- 验收标准、最终报告结论和对外交付内容。

AI 助手主要承担实现初稿、测试补充和文档整理，不替代上述决策。

## 3. 实际协作中的验证

- **接口对照**：先固定事件结构、WAL 格式、模块签名和指标名，再让实现对齐；
- **测试**：每个模块有单元测试，另有本地 WebSocket/REST 集成测试和端到端回放测试；
- **真实行情**：用 Binance 公开行情做短时 smoke 和 15 分钟采样，检查订单簿同步、WAL 和健康状态；
- **独立对照**：订单簿与朴素全量簿对拍；因子用独立公式/手算核对；回放用因子/信号/成交三个 SHA-256 对比；
- **异常场景**：断线、旧快照、WAL 截断/CRC、严格落盘和强制终止恢复都有对应测试。

## 4. 边界与经验

AI 助手能加快初稿和测试覆盖，但也可能给出过时的 API 用法、错误的手算期望，或者让测试和实现沿同一个错误方向编写。因此最终判断以可复现实验为准：测试通过、真实行情 smoke、WAL 校验和回放摘要一致，才算完成。

本项目没有把 AI 生成的代码直接当作最终答案；所有提交内容都经过本地运行和人工检查。
