# 人工智能协作说明

这个项目用了 AI 编程助手，但不是生成完直接提交：需求、接口、数据格式和验收标准由我先定，AI 出实现、测试和文档初稿；我在本地逐段审查、跑测试、跑真实行情、跑回放，发现偏差就改到测试、真实数据和回放摘要都能对上。关键决策（数据源、架构、WAL/持久化、反压、断线恢复、只做多语义、验收和最终结论）一直在我手里。

## 1. 具体纠错案例

- **旧快照回退订单簿**：AI 初版的 `apply_snapshot` 不检查快照新旧，旧快照会把簿回退，下一笔连续增量被误判为 gap。改成 `lastUpdateId < current_last_update_id` 时直接忽略，并加回归测试；验证时 `last_update_id` 和 best quote 保持不变。
- **OFI 符号方向**：AI 生成的 ask 侧符号反了，测试也沿用了错误方向，所以 `pytest` 全绿。用独立参考模型和手算对照后修正为 ask 下移 `-cur_qty`、上移 `+prev_qty`，接口文档和测试一起改，再重跑真实 WAL 回放。
- **关停 health 误报**：AI 初版在主动关停后才算 `health_final`，feed 已断开导致 `ok=false`。改成断开前记录 `health_before_shutdown`，`health_final_context=after_intentional_shutdown`；10 秒 smoke 和集成测试都验证过。
- **报告数字批量替换**：我自己的操作失误，抽象版 p99 被漏写成 1.722 ms，最小 cash 混用了期末值和逐笔过程值。对照 summary 和 fills 后改成 2.435 ms，并区分期末/过程最低现金，过程最低值用 Release 的 `cash_minima.json` 审计。

其他问题（主站不可达、WAL 可读性、aggTrade 编号连续性、fsync 测试竞态）的完整过程见 `docs/开发过程与试错.md` 和 `docs/正确性与可靠性验证.md`。

## 2. 验证与边界

AI 代码必须在本地通过 `pytest`、真实行情 smoke、WAL 校验和回放摘要才算数。AI 也可能给出过时 API 或错误的手算期望，测试本身还可能沿错误方向编写；所以关键结论只认可可复现的实验：276 个测试、真实 15 分钟采样、WAL CRC/分段哈希、回放 SHA-256、异常终止恢复。

数据源、架构、持久化语义、验收标准和最终提交内容由我决定；没有把 AI 生成的代码直接当作最终答案，所有提交内容都经过本地运行和人工检查。
