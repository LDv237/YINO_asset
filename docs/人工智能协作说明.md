# 人工智能协作说明

本文说明本项目在开发过程中如何使用 AI 编程助手，以及哪些判断和验证由我负责。

## 1. 协作方式

我的做法不是“让 AI 生成后直接提交”，而是把它当作代码初稿和测试建议的来源：

1. 我先确定需求、接口、数据格式和验收标准；
2. 让 AI 按模块生成实现初稿、测试用例和文档草稿；
3. 我在本地逐段审查并运行测试、真实行情和回放校验；
4. 发现偏差后，要求 AI 或自己修改，直到测试、真实数据和回放摘要都通过。

关键决策由我保留：数据源、架构、WAL/持久化、队列与反压、断线恢复、现货只做多语义、验收标准和最终报告结论。

## 2. 具体纠错案例

### 2.1 数据源连接失败

AI 初稿按常见写法使用 `stream.binance.com` 作为行情地址，但本机连接失败。我没有反复改代码，而是先探测多个域名，确认 `data-stream.binance.vision` 可用，再切换配置。两者都是币安现货公开行情，只是入口不同。

验证：真实 WebSocket 连接、REST 快照、15 分钟连续采样。

### 2.2 原始 WAL 不可读

AI 初版只实现了二进制 WAL。我检查交付物时发现评审无法直接打开原始行情，虽然数据没丢，但可读性不合格。

修改：保留 WAL 作为权威存储，新增 `tools/wal_export.py` 和 `tools/wal_export_csv.py`，导出 JSONL 与 CSV；正式运行导出 388,394 行 JSONL，离线样本也能 `replay --verify`。

验证：导出条数与 WAL 记录数一致，样本回放摘要一致。

### 2.3 订单簿被旧快照回退

AI 初版的 `apply_snapshot` 没有检查快照新旧。我用序列复现：

```text
快照 lastUpdateId=200 → 应用到 210
再收到 lastUpdateId=205 的旧快照
```

旧实现会把订单簿回退到 205，下一笔连续增量被误判成 gap。修改为 `lastUpdateId < current_last_update_id` 时直接忽略，不重建、不回退，并加入回归测试。

验证：构造 stale snapshot 测试，`last_update_id` 和 best quote 保持不变。

### 2.4 OFI 符号方向错误

AI 生成的 OFI 公式在 ask 侧符号反了：ask 下移被记为正，ask 上移被记为负；更麻烦的是测试也沿用了同一个错误方向，所以 `pytest` 是全绿的。

我用独立参考模型和手算对照后发现差异，修正为 ask 下移 `-cur_qty`、ask 上移 `+prev_qty`，同步修改接口文档和测试期望，并重跑真实 WAL 回放。

验证：独立参考模型对照、因子手算用例、回放摘要一致。这个案例说明“测试全绿”不等于“公式正确”。

### 2.5 成交流缺少编号连续性检查

AI 初版只对 depth 做 `U/u` 序列检查，`aggTrade.a` 没有重复/缺口检测。评审指出后，我增加按 symbol 的 `last_agg_trade_id`、重复/回退/gap/missing_ids 统计；重复事件不再二次计入因子和模拟成交。

验证：正式 15 分钟 WAL 为 0 duplicates / 0 backwards / 0 gaps；新增单元测试覆盖重复、回退和缺口。

### 2.6 关停后的健康状态被误报

AI 初版在主动关停后才计算 `health_final`，此时 feed 已断开，结果为 `ok=false`、`reason=feed_disconnected`，看起来像运行失败。

修改：在断开 feed 前记录 `health_before_shutdown`；`health_final` 不再把预期中的主动断连标为异常，并记录 `health_final_context=after_intentional_shutdown`。运行中的意外断连仍然会导致 health 失败。

验证：10 秒 smoke 的关停前/后 health 均为 true；集成测试增加断言。

### 2.7 报告数字批量替换漏项

在我批量更新报告数字时，抽象版 p99 从 2.435 ms 被漏写成 1.722 ms；同时“最小 cash”写的是期末余额最小值，而不是逐笔过程最低值。

我重新对照 summary 和 fills 序列后修正：

- p99 改为 2.435 ms；
- “期末各 symbol cash 最小值”和“过程最低现金（逐笔）”分开标注；
- 过程最低值用 `artifacts/cash_minima.json` 审计，不靠人工估算。

## 3. 验证与边界

- AI 生成的代码必须在本地通过 `pytest`、真实行情 smoke、WAL 校验和回放摘要；
- AI 可能给出过时 API 用法或错误的手算期望，测试也可能沿错误方向编写；
- 关键结论以可复现实验为准：259 个测试、真实 15 分钟采样、WAL CRC/分段哈希、回放 SHA-256、异常终止恢复；
- 数据源、架构、持久化语义、验收标准和最终提交内容由我决定。

本项目没有把 AI 生成的代码直接当作最终答案；所有提交内容都经过本地运行和人工检查。
