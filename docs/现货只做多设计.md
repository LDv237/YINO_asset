# 两种执行语义：抽象做市 vs 现货只做多

## 1. 为什么保留两套

评审当时指出一个问题：数据源是 Binance 现货，但 `Simulator` 允许负仓位，比如 BTCUSDT position = -0.003。严格按现货账户的规则，没持有的 BTC 不能卖，除非借币或加杠杆，所以负仓位和现货语义对不上。

我没有删掉原来的结果，而是保留抽象做市，另外加了一个独立的现货只做多变体。两套配置的区别在这张表里：

| 变体 | 配置 | 语义 | 用途 |
|---|---|---|---|
| 抽象做市 | `config/default.toml`，`allow_short=true`，`initial_cash_usd=0` | 带符号记账，允许负仓/负现金；从零库存运行双边做市 | 性能/链路基准，验证双边做市和确定性回放 |
| 现货只做多 | `config/spot_long_only.toml`，`allow_short=false`，`initial_cash_usd=10000` | 不允许裸卖；卖出数量不超过持仓；买入受 USDT 现金限制 | 演示“现货账户可执行”的保守版本 |

两者用的是同一套行情、因子、WAL、回放和验证代码，只换执行语义。

## 2. 只做多变体的实现

### 2.1 策略层

`MarketMaker` 在 `allow_short=false` 时，`position <= 0` 就不发 ask，只保留 bid；`position > 0` 时，ask 数量取 `min(常规报价量, position)`，向下取整到 1e-8。买入报价照发，但能不能成交由模拟器的现金约束决定。这样信号层面就不会出现“手里没币却挂卖单”的情况。

### 2.2 执行层

`Simulator` 在 `allow_short=false` 时也是同样的思路：卖出最大数量就是当前持仓，`position` 不会变成负数；买入最大数量受 `cash / (price * (1 + fee_rate))` 限制，现金不会变成负数。每个 symbol 的初始 USDT 现金是 `initial_cash_usd`，这个变体取 10,000。`total_pnl = cash + position*mark - initial_cash`，不会和初始资金混淆。借币、保证金、强平、资金费率都没有建模。

### 2.3 一个自然的后果

从零基础币库存起步，做市商一开始只能买、不能卖，只有买到库存后才会出现 ask。某些交易对在 15 分钟内可能一直等不到买入成交，所以 `fills=0`、`position=0` 是可能也合理的结果。这不是程序错误，是现货长仓约束的直接体现。

想让第一秒就能双边报价，得额外预置基础币库存；这个变体没有这么做，我不想引入一个任意的初始持仓假设。

## 3. 运行方式

```bash
# 抽象做市（性能/链路基准）
python -m tickforge live --config config/default.toml --duration 900 --out artifacts

# 现货只做多
python -m tickforge live \
  --config config/spot_long_only.toml \
  --duration 900 \
  --symbols BTCUSDT,ETHUSDT,SOLUSDT,BNBUSDT,XRPUSDT,DOGEUSDT \
  --out artifacts
```

回放与校验对两个变体完全一样：

```bash
python -m tickforge verify --run <run_dir>
python -m tickforge replay --run <run_dir> --out <run_dir>-replay --verify
```

## 4. 结果

### 4.1 同一份 WAL 的受控对照

我把正式抽象运行的 15 分钟 WAL 原样重放，只把执行语义切换为只做多。市场数据、订单簿、因子完全相同；信号数量相同，但 ask 字段和成交结果按现货约束变化。

```bash
python tools/replay_spot_long_only.py   --run artifacts/runs/20261020T072820Z-53b5   --out artifacts/experiments/variants/spot_long_only_same_wal_final
```

| 指标 | 抽象做市（性能基准） | 只做多（现货执行语义） |
|---|---:|---:|
| 原始帧 / WAL 记录 | 388,388 / 388,394 | 388,388 / 388,394 |
| 因子快照 / 信号 | 43,309 / 43,309 | 43,309 / 43,309 |
| fills | 10,177 | 3,077 |
| 负仓位 symbol 数 | 1 | **0** |
| 负现金 symbol 数 | 6 | **0** |
| 期末各 symbol cash 最小值 | -9,340.86 | 8,511.53 |
| 过程最低现金（逐笔） | -9,588.12 | 8,021.74 |
| 结束 position（各 symbol） | 含负值（BNB -0.30767748） | 全部 0 |
| 初始现金合计 | 0 | 60,000（6 × 10,000） |
| 总 PnL（相对初始） | -19,358.18 | -3,687.49 |

这份对照最能说明问题：同样的行情和因子，只做多版没有出现任何负仓位或负现金；因为它不能裸卖，成交数从 10,177 降到 3,077，并且最终全部平仓。

把 fills 再拆一层：

| 口径 | 信号 | fills | 买 / 卖笔数 | fill / signal |
|---|---:|---:|---:|---:|
| 抽象做市 53b5 | 43,309 | 10,177 | 5,240 / 4,937 | 23.5% |
| 同一 WAL 只做多 | 43,309 | 3,077 | 1,255 / 1,822 | 7.1% |
| 独立只做多 91ac | 41,265 | 2,133 | 864 / 1,269 | 5.2% |

同一份 WAL 下，只做多的 fill/signal 从 23.5% 降到 7.1%，这是执行语义的直接结果：`position <= 0` 时不发 ask，买入受每 symbol 10,000 USDT 初始现金限制，卖出只能卖已有持仓。三个 run 的 `risk_truncated` / `risk_rejected` 都是 0，说明约束主要拦在“报价端”（不发单、缩量），不是成交时大量拒单；fills 变少主要是可成交的报价变少。

注意 91ac 是独立的 15 分钟窗口，行情负载和 53b5 不同，2,133 不能直接和 10,177 比；受控比较看同一 WAL 的 3,077。91ac 的买/卖笔数是 864 / 1,269，期末 BNB 0.07000001、DOGE 76.0，其余为 0——多出来的卖出来自已持有的库存，不是裸卖。

### 4.3 严格落盘版（spot long-only + fsync always）

`config/spot_long_only_durable.toml` 只把 WAL 改成 `fsync_policy="always"`，现货只做多的约束不动。15 分钟的结果是：`run_id=20261020T082850Z-6db8`，900.172 s；272,784 原始帧 / 272,802 条 WAL（18 个快照），每条记录 fsync 后才处理；37,802 信号 / 1,578 fills，负仓位和负现金均为 0。过程最低现金 8,967.92，期末各 symbol cash 最小值 9,458.20；p50 3.444 ms / p99 5.793 ms / p999 9.742 ms。该次运行观察到 2 次网络重连（data gap 1.151 s / 0.925 s），重连的具体原因尚未隔离，不能唯一归因到 fsync；期间触发 12 次 resync、18 个快照，收到的原始帧 0 丢失；`verify` 与 `replay --verify` 都通过。

这版我拿它当严格持久化的合规证据，interval 版仍然是性能/语义对照。断线窗口内的 gap 是交易所端未送到的数据，不是 WAL 丢帧，记录在 `summary.data_gaps`；公开 WS 不会自动补发，REST aggTrades 可补聚合成交，但本 demo 尚未实现 REST 补采，历史 depth 增量不可恢复。

### 4.4 结论

抽象做市版保留原结果，用来展示双边做市和回放；它明确不代表现货账户。只做多版在同一份 WAL 和独立 15 分钟运行中都没有出现负仓位或负现金，满足现货“不能卖未持有的币”的约束。它不是“更高收益”的版本，fills 更少，期末库存也不同；题目不考察收益，重点在语义正确和链路可复现。

## 5. 解释与局限

- 抽象做市版不是现货账户，允许负仓位是刻意选择，用于从零库存跑双边做市；不能据此声称现货可做空。
- 只做多版是更严格的“现货执行语义”，但仍不是真实账户：没有真实下单、订单队列、撤单延迟、借币、保证金、交易所风控。
- 只做多版每 symbol 初始 10,000 USDT 是人为设置的模拟资金；不同初始资金会影响 fills 和 PnL。
- 成交判断已启用基于实际成交时间 `T` 的 quote-time guard：`T` 早于报价时不会成交；历史 run 的执行结果由同一份 WAL 重算（`T` guard + tick 取整），延迟/资源仍是原始 live 采集。模拟撮合的整体简化仍限制 fill/PnL 的真实性。
- 两个版本都不以收益为评价目标；比较重点是仓位/现金约束、信号行为、回放确定性。
- 性能数据以抽象做市版为基准；现货执行语义以只做多版为准。不要把抽象版的负仓位当成现货事实，也不要用它的 PnL 评价现货策略。
