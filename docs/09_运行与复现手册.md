# 运行与复现手册

这份手册是我自己跑这个项目时整理下来的，从环境准备到运行、校验、归档都在里面。命令可以直接复制执行。

## 1. 环境

我本机是 Windows 11，Python 3.14.7，12 个逻辑核，195 GB 可用磁盘；代码本身要求 Python 3.11 以上。依赖都锁在 `requirements-lock.txt`，主要有 aiohttp 3.14.5、orjson 3.13.0、websockets 17.3、psutil 7.2.2，以及它们的传递依赖；四个 `requirements*.txt` 的区别见 `docs/08_依赖与运行环境.md`。

项目不需要 API Key，只要能访问下面两个地址：

- `wss://data-stream.binance.vision/stream`
- `https://data-api.binance.vision/api/v3/depth`

运行前先做一次连通性自检：

```bash
curl -sS -m 8 -o /dev/null -w '%{http_code}\n' https://data-api.binance.vision/api/v3/ping
```

返回 `200` 就说明网络通。如果所在网络访问不了这个域名，可以在 `config/default.toml` 里把 `ws_url` / `rest_url` 换成其他公开行情源；消息结构要保持一致，或者在 `feed/` 里加一个适配器。

## 2. 安装

```bash
cd YINO_asset   # git clone 得到的目录；如果是解压提交包，cd 到包根目录
python -m pip install -r requirements-lock.txt
```

Windows PowerShell 下我习惯先设一下编码：

```powershell
$env:PYTHONUTF8 = "1"
```

## 3. 15 分钟实测

启动方式有三套，按手头的终端选：

```bash
# bash / Git Bash
bash scripts/run_live_15m.sh

# Windows PowerShell
powershell -ExecutionPolicy Bypass -File scripts/run_live_15m.ps1

# 直接命令（可覆盖参数）
python -m tickforge live \
  --config config/default.toml \
  --duration 900 \
  --symbols BTCUSDT,ETHUSDT,SOLUSDT,BNBUSDT,XRPUSDT,DOGEUSDT \
  --out artifacts
```

运行起来以后，我会另开一个终端看状态：

```bash
curl http://127.0.0.1:9100/healthz
curl http://127.0.0.1:9100/status
curl http://127.0.0.1:9100/metrics | head
```

`/healthz` 返回 200，表示这几件事都正常：连接正常、行情新鲜、所有订单簿已同步、WAL 没有错误、处理队列没有滞后（`processing_lag_ms` 和最老待处理事件的 `oldest_pending_ms` 都在阈值内）。

900 秒是从收到第一条行情开始算的，首次启动建立连接的耗时不计入测量窗口；窗口内发生重连时，重连停顿仍计入连续墙钟窗口。正常结束后进程退出码是 0，`summary.json.clean_shutdown` 应该是 `true`。

如果需要更严格的落盘语义，可以强制每条记录都 fsync：

```bash
python -m tickforge live --duration 60 --fsync-policy always --out artifacts
```

代价是延迟会明显上升。


## 5. 校验与回放

包内主结果的 raw/derived 在 `run_data.tar.xz` 里，先解压再校验：

```bash
python scripts/extract_main_run.py 运行材料/01_主结果_现货_9821
python -m tickforge verify --run 运行材料/01_主结果_现货_9821
python -m tickforge replay --run 运行材料/01_主结果_现货_9821 \
  --out 运行材料/01_主结果_现货_9821-replay --verify
python -m tickforge show --run 运行材料/01_主结果_现货_9821
python tools/analyze_run.py 运行材料/01_主结果_现货_9821
```

如果刚跑了一次新的 live，把 `--run` 指向 `artifacts/runs/<run_id>` 即可；导出 JSONL/CSV 用 `tools/wal_export*.py`，见 [`tools/README.md`](../tools/README.md)。`replay` 默认写到 `<run_dir>-replay`，目录非空会拒绝覆盖；命令显式带 `--out` 更稳。

我判断一次运行是否通过，看这三条：

- `verify`：`ok=true`，WAL 每条记录 CRC 通过，记录数与 `summary.json` 一致，manifest 分段哈希一致；
- `replay --verify`：`deterministic=true`、`verified=true`，因子/信号/成交三个 SHA-256 与运行目录中的 derived 一致，计数一致；replay 总是比较摘要，`--verify` 只决定不一致时是否返回非零退出码；
- `summary.json.reconciliation.lost_raw_frames == 0`，`drained == true`。

## 6. 制作离线样本

为了能在不访问交易所的情况下复现完整回放，从一次真实运行里裁出前 N 条 WAL 记录，生成样本和离线参考摘要：

```bash
# trim_run 拒绝覆盖非空目录，换一个新输出目录
python tools/trim_run.py --run artifacts/runs/<run_id> \
  --out samples/demo_run_new --records 20000
python tools/make_sample_reference.py --sample samples/demo_run_new
python -m tickforge replay --run samples/demo_run_new \
  --out samples/demo_run_new-replay --verify
```

`make_sample_reference.py` 生成 replay 对比用的 `summary.json`；少了这一步，`replay --verify` 会缺参考摘要。需要可读 JSONL/CSV 时用 `tools/wal_export*.py` 另导。整个过程不需要访问交易所。

## 7. Docker

```bash
docker compose build
docker compose up --abort-on-container-exit
```

输出挂载 `./artifacts → /data`，服务端口 `127.0.0.1:9100`；容器以 root 运行只为写 bind mount，生产应改固定 UID。构建慢时可设 `PIP_INDEX_URL` 指向镜像站。

本机 Docker Desktop WSL2 组件不完整，引擎无法启动；GitHub Actions 干净环境已完成 build、60 秒 live、verify、replay。关键证据在 `运行材料/03_验证证据/docker_ci/`；完整 build/日志在 run 39731008808 的 GitHub Actions artifact `docker-verify-evidence`（Release 的 artifacts zip 内为 2026-10-20 的 Docker 证据）；复跑见 [10_Docker构建与运行验证.md](10_Docker构建与运行验证.md) 和 [scripts/docker_verify.sh](../scripts/docker_verify.sh)。Release 另附 `tickforge-0.1.0.tar.gz`，`docker load` 后可直接运行。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 启动 120 秒无数据后退出 | 先检查 `data-stream.binance.vision` 的连通性，再看 `logs/tickforge.log` 里的 connect 错误 |
| `/healthz` 一直 503 | 看 `reasons`：`waiting_for_data` / `feed_disconnected` / `books_unsynced` / `processing_lag` |
| 端口 9100 被占用 | 用 `--http-port 0` 换随机端口，启动日志和状态里能看到实际端口；也可以直接换一个端口 |
| `books_unsynced` 持续 | 检查 REST `/api/v3/depth` 是不是被限频，日志里找 `snapshot fetch failed` |
| WAL 错误 | 检查磁盘空间和权限；`wal.error` 非空时程序会停止接收，已经落盘的数据仍然可以回放 |
| replay 摘要不一致 | 先跑 `verify`；如果 WAL 尾部截断或者手工改过配置，注意回放参数来自运行时的 `config.json`，不应该被当前环境覆盖 |
| 想只跑 1 分钟 | 用 `--duration 60`，`summary.window_s` 应该约为 60 |
| 想减少磁盘 | 用 `--symbols BTCUSDT`；调大 `wal.segment_bytes` 不会减少总量，还是要在运行后归档或删除 |

## 9. 归档与交付

```bash
# WAL 压缩（原始 JSON 文本压缩比通常 >8x）
cd artifacts/runs/<run_id>
tar -czf raw-<run_id>.tar.gz raw
sha256sum raw-<run_id>.tar.gz

```

归档时先压缩 WAL。完整交付包包含代码、文档、测试和离线样本；完整 artifacts 见 Release。

交付材料包括：完整交付包；`summary.json`、`manifest.json`、WAL 压缩包或离线样本按需另附。
