# 人工智能协作说明

本项目使用 AI 编程助手辅助开发：需求、接口、数据格式和验收标准由我确定，AI 负责实现、测试和文档初稿；我在本地逐段审查，并运行测试、真实行情和回放，发现偏差即修正，直至测试、真实数据和回放摘要一致。关键决策（数据源、架构、WAL/持久化、反压、断线恢复、现货执行语义、验收和最终结论）均由我作出。

## 1. 具体纠错案例

- **旧快照回退订单簿**：AI 初版的 `apply_snapshot` 不检查快照新旧，旧快照会把簿回退，下一笔连续增量被误判为 gap。改成 `lastUpdateId < current_last_update_id` 时直接忽略，并加回归测试；验证时 `last_update_id` 和 best quote 保持不变。
- **OFI 符号方向**：AI 生成的 ask 侧符号反了，测试也沿用了错误方向，因此 `pytest` 全部通过。用独立参考模型和手算对照后修正为 ask 下移 `-cur_qty`、上移 `+prev_qty`，接口文档和测试一起改，再重跑真实 WAL 回放。
- **关停 health 误报**：AI 初版在主动关停后才算 `health_final`，feed 已断开导致 `ok=false`。改成断开前记录 `health_before_shutdown`，`health_final_context=after_intentional_shutdown`；10 秒 smoke 和集成测试都验证过。
- **报告数字核对**：抽象版 p99 曾误写为 1.722 ms，最低 cash 曾混用期末值与逐笔过程值。对照 summary 和 fills 后，p99 修正为 2.435 ms，并区分期末最低现金与过程最低现金；过程最低值与 Release 的 `cash_minima.json` 核对。

其他问题（主站不可达、WAL 可读性、aggTrade 编号连续性、fsync 测试竞态）的完整过程见 `docs/06_开发过程与问题记录.md` 和 `docs/04_正确性与可靠性验证.md`。

## 2. 验证与边界

AI 代码必须在本地通过 `pytest`、真实行情 smoke、WAL 校验和回放摘要，方可视为有效。AI 也可能给出过时 API 或错误的手算期望，测试本身还可能沿错误方向编写；所以关键结论只认可可复现的实验：280 个测试、真实 15 分钟采样、WAL CRC/分段哈希、回放 SHA-256、异常终止恢复。

数据源、架构、持久化语义、验收标准和最终提交内容由我决定；所有提交内容均经过本地运行与人工检查，AI 生成的代码需通过上述验证后才纳入提交。
