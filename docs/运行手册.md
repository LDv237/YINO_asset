# 运行手册

这份手册是我自己跑这个项目时整理下来的，从环境准备到运行、校验、归档都在里面。命令可以直接复制执行。

## 1. 环境

我本机是 Windows 11，Python 3.14.7，12 个逻辑核，195 GB 可用磁盘；代码本身要求 Python 3.11 以上。依赖都锁在 `requirements-lock.txt`，主要有 aiohttp 3.14.5、orjson 3.13.0、websockets 17.3、psutil 7.2.2，以及它们的传递依赖；四个 `requirements*.txt` 的区别见 `docs/依赖说明.md`。

项目不需要 API Key，只要能访问下面两个地址：

- `wss://data-stream.binance.vision/stream`
- `https://data-api.binance.vision/api/v3/depth`

跑之前我会先做一次连通性自检：

```bash
curl -sS -m 8 -o /dev/null -w '%{http_code}\n' https://data-api.binance.vision/api/v3/ping
```

返回 `200` 就说明网络通。如果所在网络访问不了这个域名，可以在 `config/default.toml` 里把 `ws_url` / `rest_url` 换成其他公开行情源；消息结构要保持一致，或者在 `feed/` 里加一个适配器。

## 2. 安装

```bash
cd 一诺资产
python -m pip install -r requirements-lock.txt
```

Windows PowerShell 下我习惯先设一下编码：

```powershell
$env:PYTHONUTF8 = "1"
```

## 3. 15 分钟实测

启动方式有三套，按手头的终端选：

```bash
# bash / Git Bash
bash scripts/run_live_15m.sh

# Windows PowerShell
powershell -ExecutionPolicy Bypass -File scripts/run_live_15m.ps1

# 直接命令（可覆盖参数）
python -m tickforge live \
  --config config/default.toml \
  --duration 900 \
  --symbols BTCUSDT,ETHUSDT,SOLUSDT,BNBUSDT,XRPUSDT,DOGEUSDT \
  --out artifacts
```

运行起来以后，我会另开一个终端看状态：

```bash
curl http://127.0.0.1:9100/healthz
curl http://127.0.0.1:9100/status
curl http://127.0.0.1:9100/metrics | head
```

`/healthz` 返回 200，表示这几件事都正常：连接正常、行情新鲜、所有订单簿已同步、WAL 没有错误、处理队列没有滞后。

900 秒是从收到第一条行情开始算的，启动阶段建立连接的耗时不计入测量窗口。正常结束后进程退出码是 0，`summary.json.clean_shutdown` 应该是 `true`。

如果需要更严格的落盘语义，可以强制每条记录都 fsync：

```bash
python -m tickforge live --duration 60 --fsync-policy always --out artifacts
```

代价是延迟会明显上升。

## 4. 产物

一次运行结束后，`artifacts/` 的结构大致是这样：

```text
artifacts/
  runs/<run_id>/        完整运行目录
    config.json         运行参数与环境快照（回放使用）
    raw/                原始 WAL 分段，二进制格式见 docs/接口设计.md
    derived/            factors / signals / fills JSONL
    logs/tickforge.log  结构化 JSON 日志（滚动）
    summary.json        计数、速率、延迟分位、WAL、对账、摘要哈希
    manifest.json       文件清单 + WAL 分段 SHA-256
    sha256sums.txt      产物校验和
    replay/             （运行回放后生成）
  exports/              原始 WAL tar、可读 JSONL、CSV 压缩包
  summaries/            正式/变体运行摘要、清单、成交 CSV
  evidence/             成交编号、现金最低值、活跃度、崩溃恢复证据
  logs/                 控制台日志与健康快照
  experiments/          fsync 对照、旧 smoke、同一 WAL 变体等
运行材料/                面向面试官的分类附件副本（已同步到 Git）
```

`runs/<run_id>/` 是一次运行的完整快照，回放和校验都从这里取数据。`exports/`、`summaries/`、`evidence/` 按用途放了导出文件、摘要和验证证据。`运行材料/` 是给面试官看的副本，已同步到 Git。

## 5. 校验与回放

跑完以后我会按下面的顺序校验。先取最近一次运行目录：

```bash
RUN_DIR=$(ls -td artifacts/runs/* | head -1)

python -m tickforge verify --run "$RUN_DIR"
python -m tickforge replay --run "$RUN_DIR" --out "$RUN_DIR-replay" --verify
python -m tickforge show --run "$RUN_DIR"
python tools/analyze_run.py "$RUN_DIR"

# 人类可读的原始行情（WAL 的只读视图）
python tools/wal_export.py --run "$RUN_DIR" --out "$RUN_DIR/raw_events.jsonl.gz"

# 按事件类型导出 CSV
python tools/wal_export_csv.py --run "$RUN_DIR" --out-dir "$RUN_DIR/csv"
```

`replay` 默认写到 `<run_dir>-replay`；目录非空会拒绝，不会覆盖原来的 `replay/` 证据。上面的命令显式带 `--out`，方便把回放产物放到指定目录。

我判断一次运行是否通过，看这三条：

- `verify`：`ok=true`，WAL 每条记录 CRC 通过，记录数与 `summary.json` 一致，manifest 分段哈希一致；
- `replay --verify`：`deterministic=true`、`verified=true`，因子/信号/成交三个 SHA-256 与运行目录中的 derived 一致，计数一致；replay 总是比较摘要，`--verify` 只决定不一致时是否返回非零退出码；
- `summary.json.reconciliation.lost_raw_frames == 0`，`drained == true`。

## 6. 制作离线样本

为了能在不访问交易所的情况下复现完整回放，我从一次真实运行里裁出前 N 条 WAL 记录，连同快照一起生成样本：

```bash
python tools/trim_run.py \
  --run artifacts/runs/<run_id> \
  --out samples/demo_run \
  --records 20000
python -m tickforge replay --run samples/demo_run --out samples/demo_run-replay --verify
```

样本目录里有 `config.json`、`raw/`、`sample_manifest.json`、`summary.json`，还有可读的 JSONL 和 CSV。这里的 `summary.json` 是离线参考摘要，由 `tools/make_sample_reference.py` 生成，不是 live 运行的结果。整个过程不需要访问交易所。

## 7. Docker

```bash
docker compose build
docker compose up --abort-on-container-exit
```

几个配置点：

- 输出挂载：`./artifacts` → `/data`，容器内运行目录为 `/data/runs/<run_id>`；
- 服务端口：`127.0.0.1:9100`；
- 回放：`docker compose run --rm tickforge replay --run /data/runs/<run_id> --out /data/runs/<run_id>-replay --verify`；
- 构建慢时可使用镜像：`PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple docker compose build`；
- 容器为 demo 便利以 root 运行，以便写 bind mount；生产应改固定 UID 并匹配卷权限。

本机（Windows）的 Docker Desktop WSL2 组件不完整，引擎起不来，所以本机没有执行构建和运行。2026-10-21 已在 GitHub Actions 的干净环境用当前 main（commit `83d4c1a`）完成 build、容器版本、离线 sample replay、60 秒 live、verify 和 replay（run 39552903429，image sha256:a960d6c2…），证据在 `artifacts/experiments/docker/ci/`。Release 另附 `tickforge-0.1.0.tar.gz`，`docker load` 后可直接运行；本机或其他 Docker 主机可以按 [Docker构建验证.md](Docker构建验证.md) 和 [scripts/docker_verify.sh](../scripts/docker_verify.sh) 复跑。Dockerfile 用的是官方 `python:3.14-slim`，入口和本地 `python -m tickforge` 完全一致。

## 8. 常见问题

| 现象 | 排查 |
|---|---|
| 启动 120 秒无数据后退出 | 先检查 `data-stream.binance.vision` 的连通性，再看 `logs/tickforge.log` 里的 connect 错误 |
| `/healthz` 一直 503 | 看 `reasons`：`waiting_for_data` / `feed_disconnected` / `books_unsynced` / `processing_lag` |
| 端口 9100 被占用 | 用 `--http-port 0` 换随机端口，启动日志和状态里能看到实际端口；也可以直接换一个端口 |
| `books_unsynced` 持续 | 检查 REST `/api/v3/depth` 是不是被限频，日志里找 `snapshot fetch failed` |
| WAL 错误 | 检查磁盘空间和权限；`wal.error` 非空时程序会停止接收，已经落盘的数据仍然可以回放 |
| replay 摘要不一致 | 先跑 `verify`；如果 WAL 尾部截断或者手工改过配置，注意回放参数来自运行时的 `config.json`，不应该被当前环境覆盖 |
| 想只跑 1 分钟 | 用 `--duration 60`，`summary.window_s` 应该约为 60 |
| 想减少磁盘 | 用 `--symbols BTCUSDT`；调大 `wal.segment_bytes` 不会减少总量，还是要在运行后归档或删除 |

## 9. 归档与交付

```bash
# WAL 压缩（原始 JSON 文本压缩比通常 >8x）
cd artifacts/runs/<run_id>
tar -czf raw-<run_id>.tar.gz raw
sha256sum raw-<run_id>.tar.gz

# 代码/文档/样本（不含完整 artifacts）
cd ../../..
zip -r 代码包.zip tickforge tests tools scripts config docs samples README.md 交付说明.md 笔试报告.md \
  Dockerfile docker-compose.yml requirements*.txt pyproject.toml
```

归档时我先把 WAL 压掉。代码、文档和样本单独打一个包，完整 artifacts 不放进这个压缩包。

邮件交付时附上：代码压缩包、`summary.json`、`manifest.json`、WAL 压缩包或离线样本、性能/验证文档与报告。
