# 运行产物索引

正式运行的目录和附件，我按用途分开存放，避免把历史实验、日志和交付文件混在一起。

## 1. 目录分类

| 目录 | 内容 |
|---|---|
| `artifacts/runs/` | 每次运行的完整目录（WAL、derived、日志、summary、manifest、replay） |
| `artifacts/exports/` | 正式运行的 WAL 压缩包、JSONL、CSV 压缩包 |
| `artifacts/summaries/` | 正式运行与变体运行的摘要、清单、成交 CSV |
| `artifacts/evidence/` | 成交编号、现金最低值、交易活跃度、崩溃恢复等验证证据 |
| `artifacts/logs/` | 控制台日志与健康快照 |
| `artifacts/experiments/` | fsync 对照、旧 smoke、同一 WAL 变体等实验 |
| `交付材料/` | 面向面试官的完整材料副本与索引（已同步到 Git） |

要复现一次运行，进 `artifacts/runs/`；只想看结果，去 `artifacts/summaries/` 和 `artifacts/exports/`。

## 3. 正式运行产物

正式性能基准这次运行，目录结构是这样的：

```text
artifacts/runs/20261020T072820Z-53b5/
  raw/                     2 个 WAL 分段，388,394 条记录
  derived/                 factors / signals / fills JSONL
  logs/tickforge.log       结构化运行日志
  summary.json             计数、速率、延迟分位、资源、对账、摘要
  manifest.json            文件与 WAL 分段 SHA-256
  sha256sums.txt           产物校验和
  replay/                  回放产物与 replay_summary.json
```

`raw/` 里是 2 个 WAL 分段、388,394 条记录；`derived/` 下是因子、信号和成交的 JSONL；`summary.json` 和 `manifest.json` 分别记运行指标和文件哈希；`replay/` 是回放后生成的。

交付附件在下面，路径和大小都列出来了：

```text
artifacts/summaries/附件校验和.txt            附件校验和
一诺笔试交付包.zip                            代码、文档、测试、样本
```

这些文件分别对应正式运行的原始 WAL、可读 JSONL、CSV 视图、summary 和 manifest；代码包单独放在仓库根目录。

本次交付的 15 分钟 run 执行结果（signals/fills/PnL/digests）由同一份原始 WAL 用 quote-time guard + tick 取整重算；`logs/` 下的控制台日志是原始 live 采集，末尾的 fills 计数是重算前的 live 值。延迟、资源、健康仍是原始 live 数据。`summary.json` 的 `execution_replay` 字段记录了重算来源、quote-time guard、tick 取整和重算时间。
