# 依赖与运行环境

仓库根目录有四个 `requirements*.txt`。四个文件按“直接依赖 / 完整锁文件”和“运行时 / 测试”两个维度组合，内容互不重复。第一次阅读项目时可按下面的表选择文件。

## 1. 四个文件分别是什么

| 文件 | 内容 | 用途 | 是否推荐直接安装 |
|---|---|---|---|
| `requirements.txt` | 4 个运行时直接依赖：`aiohttp`、`orjson`、`websockets`、`psutil` | 说明“我直接用了什么”；不包含传递依赖 | 不建议作为复现安装入口 |
| `requirements-lock.txt` | 运行时依赖的**完整闭包**：直接依赖 + `aiohappyeyeballs`、`aiosignal`、`attrs`、`frozenlist`、`idna`、`multidict`、`propcache`、`yarl` 等传递依赖 | 运行时权威锁；Dockerfile、README、交付说明都用它 | **运行时安装用这个** |
| `requirements-dev.txt` | `-r requirements-lock.txt` + `pytest` + `pytest-asyncio` | 测试工具的直接依赖；只锁了 pytest 本身，没有锁 pytest 的传递依赖 | 不建议作为复现安装入口 |
| `requirements-dev-lock.txt` | 测试环境的**完整闭包**：运行时依赖 + pytest 及其传递依赖（`colorama`、`iniconfig`、`packaging`、`pluggy`、`Pygments`） | 测试环境权威锁；280 个测试用它复现 | **跑测试用这个** |

## 2. 最短安装命令

运行时（live / replay / verify）：

```bash
python -m pip install -r requirements-lock.txt
```

测试（pytest）：

```bash
python -m pip install -r requirements-dev-lock.txt
python -m pytest -q
```

Docker 镜像内部也是 `pip install -r requirements-lock.txt`，见根目录 `Dockerfile`。

## 3. 为什么保留四份

- `requirements.txt` / `requirements-dev.txt` 是“直接依赖声明”，方便人快速看出项目主动用了哪些库，也方便以后重新生成锁文件；
- `requirements-lock.txt` / `requirements-dev-lock.txt` 是“完整锁文件”，保证换机器、换虚拟环境时安装到完全相同的版本；
- 真正安装时只需要两个 lock 文件。非 lock 文件不会影响运行，也不是额外依赖。

## 4. 环境要求

- Python 3.11+；本次交付在 Python 3.14.7、Windows 11 上验证；
- 只访问 Binance 公开行情接口，不需要 API Key；
- 测试数量：`280 passed`，用 `requirements-dev-lock.txt` 复现。

更完整的运行步骤见 `docs/09_运行与复现手册.md`；依赖锁定策略就是本文 §3。
